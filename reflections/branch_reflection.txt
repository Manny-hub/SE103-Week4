Why teams use branches:
Teams use branches to keep different lines of development separate. A branch allows developers to work on a feature or fix without changing the main branch immediately. This helps prevent unfinished work from affecting the stable version of the project. Team members can review changes before they are merged into main. Branches also make it easier to track what each change is intended to accomplish.

Why add-reflection is a better branch name than test or changes:
add-reflection clearly describes the purpose of the branch. Names such as test or changes are too general and do not tell other team members what is being worked on.

What stays protected when I work on a branch instead of main:
The main branch stays protected from unfinished or incorrect changes while I work on my branch. I can make and test changes separately before they are reviewed and merged into main.
